# 실습: REQ-TASK-001 과제 등록 테스트 케이스 (동등분할 · 경계값 분석)

- 대상 요구사항: REQ-TASK-001 과제 등록 (Critical)
- 검증 규칙 출처: REQ-TASK-006 과제 입력값 검증 (REQ-TASK-001에는 입력 규칙이 없어서 006의 규칙을 씀)
- 관련 목표와 결함: G1 과제 등록과 입력 검증, F6 입력 검증 누락 (`research/faults/catalog.yaml`)
- 기준 데이터: `backend/src/seed.ts` (seed-v1, 사용자 1명 `student@studyflow.test`, 과목 3개, 과제 12개)
- 현재 구현 상태 (2026-11-19 기준): 과제 등록 UI와 `POST /tasks` API가 아직 없다. 아래 케이스는 명세 기준으로 만들었고, 기능이 구현되면 그대로 실행한다.

## 1. 입력 조건과 동등분할

REQ-TASK-006 규칙:

- 과제명은 필수이다.
- 과목은 필수이다.
- 마감일은 필수이다.
- 과제명은 공백만으로 구성될 수 없다.

설명은 REQ-TASK-001 Actions 5에 "필요하면 입력한다"고 되어 있으므로 선택 항목으로 본다.

| 입력 | 유효 클래스 | 무효 클래스 |
|---|---|---|
| 과제명 | **V1** 공백이 아닌 문자를 1개 이상 포함한 문자열 | **I1** 빈 문자열 `""` · **I2** 공백만 있는 문자열 |
| 과목 | **V2** 로그인한 사용자의 과목 중 하나 (데이터마이닝, 머신러닝, 네트워크과학) | **I3** 선택하지 않음 |
| 마감일 | **V3** 올바른 날짜 | **I4** 입력하지 않음 |
| 설명 | **V4** 입력함 · **V5** 비워 둠 (선택 항목) | (없음) |

## 2. 경계값

명세에 최대 길이나 날짜 범위가 없어서, 실제로 정해진 경계는 과제명의 **최소 길이**와 **공백 제거(trim) 후 길이**뿐이다.

| 경계 | 무효 쪽 값 | 유효 쪽 값 |
|---|---|---|
| 과제명 길이 0 / 1 | `""` (길이 0) | `"가"` (길이 1) |
| 공백 제거 후 길이 0 / 1 | `" "` (원래 길이 1, trim 후 0) | `"가"` (trim 후 1) |
| 설명 길이 0 (선택 항목의 하한) | (해당 없음) | `""` (길이 0, 유효) |

`" "`와 `"가"`는 원래 길이가 둘 다 1이다. 그래서 두 결과가 다르면 검증이 원래 길이가 아니라 trim한 길이로 이루어진다는 것을 확인할 수 있다.

### 기대 결과 확인 방법

- **유효 케이스 (TC-01, TC-02):**
  - 목록 행 수가 12에서 13으로 바뀐다.
  - `GET /api/tasks/summary`의 `total`이 13이다.
  - `GET /api/tasks`에 새 과제가 나온다. 이 API는 `user_id = 1`인 과제만 돌려주므로, 새 과제가 나오면 REQ-TASK-001의 "현재 로그인한 사용자에게 귀속된다"는 조건도 확인된다.
  - 목록은 생성일 내림차순이므로 새 과제가 첫 행에 나와야 한다 (REQ-TASK-002).
- **무효 케이스 (TC-03 ~ TC-06):**
  - 오류 메시지가 화면에 표시된다.
  - 목록 행 수와 `summary.total`이 12 그대로이다.
  - 입력한 과제명으로 된 행이 새로 생기지 않는다.
  - F6은 백엔드 결함이므로, API가 생기면 같은 입력을 `POST`로 직접 보내 4xx 응답과 미저장을 함께 확인하는 것이 좋다. 프론트엔드 검증만으로는 F6을 잡을 수 없다.

## 5. 명세의 빈틈 (경계값 분석에서 발견)

명세에 아래 규칙이 없어서 경계값을 정할 수 없었다. 규칙이 정해지면 테스트 케이스를 추가한다.

1. **과제명 최대 길이:** 정해지지 않았다. DB는 `TEXT`라 길이 제한이 없다. 예를 들어 최대 100자로 정하면 100자(유효)와 101자(무효)를 추가한다.
2. **마감일 범위:** 지난 날짜나 오늘 날짜를 허용하는지 정해지지 않았다. 지난 날짜를 막는다면 오늘 2026-11-19(유효), 어제 2026-11-18(무효)이 경계값이다.
3. **과제명 앞뒤 공백:** `" 가 "`를 저장할 때 trim한 값으로 저장할지 정해지지 않았다.
4. **과목 무결성 (API):** UI는 드롭다운이라 다른 값을 고를 수 없다. 하지만 API로는 존재하지 않는 `subjectId`(예: 999)나 다른 사용자의 과목을 보낼 수 있으므로, 이를 막는 무효 클래스가 필요하다. 지금은 사용자가 1명뿐이라 다른 사용자 사례는 seed에 없다.
5. **오류 메시지 문구:** "입력 오류 메시지가 표시된다"고만 되어 있다. 자동화 테스트에서 확인하려면 문구나 표시 위치(필드 옆인지 상단인지)를 정해야 한다.
